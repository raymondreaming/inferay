# Inferay GPUI

GPUI is Inferay's only desktop renderer. The GPUI-only cutover removes the Solid UI, webview host, browser build chain, and web renderer tests. Git history preserves that implementation. Future development and incremental testing happen here; this milestone does not claim complete feature parity.

Shared Rust application behavior remains in `native/core`, `native/presentation`, `native/diff-engine`, and `native/server`.

## Build and run

`bun run build:gpui` creates `build/gpui/Inferay Native.app`. `bun run dev:gpui` also opens it. The bundle has its own `com.inferay.gpui-preview` identity and is ad-hoc signed. Rust, Xcode command-line tools, and macOS are required.

When the shipping app is running, connect the preview to its existing local backend:

```sh
INFERAY_EXTERNAL_BACKEND_ADDR=127.0.0.1:<actual-port> bash scripts/dev-gpui.sh
```

The build script preserves this address in the preview bundle's environment. Without it, startup runs the shared Rust backend for the selected profile. A profile lock prevents two current backends owning the same profile; the preview also refuses embedded startup when an older host has tracked live agents. Do not start a second runtime against an active profile. `INFERAY_USER_DATA_DIR` selects an isolated profile for development and tests.

An older external backend may lack newer endpoints. In particular, the installed backend used during this audit returns 404 for Database. The current shared backend supports the database explorer and is verified using a temporary profile.

## Current behavior

- The window first appears after saved appearance and scene decoding finish; scene images pass decoded pixels directly to GPUI. Sidebar chat close stops the running agent through the backend, removes the saved pane, and retains other chats and drafts. Closing the last chat opens a new one.
- Restores active project tabs, repository bindings, chat grids, selected chat, sidebar dimensions, saved drafts, provider defaults, font, background, syntax theme, and graph columns. New chats get canonical saved pane identities and project associations. Draft edits are saved through the shared preferences service. Tab/chat selection, sidebar visibility, and completed sidebar width changes persist through the shared services; switching projects retains local selection and drafts. Project and Other chats grid split resizes persist through the shared dock service in order, using the same responsive three-column grid as the main app.
- Restores saved transcripts and subscribes to live updates using the shared epoch/revision replica, with reconnect repair and tail following that pauses when reading earlier messages. A latest-message button restores following; sidebar titles refresh on live summary events and reconnect. The native transcript owner publishes prepared rows and viewport changes together, retaining scroll anchors and immutable message sources. Variable-height native lists lay out visible transcript rows. Markdown text, styles, links, and tool details are prepared off the UI thread and retained across redraws; queued stream bursts coalesce before preparation while preserving every activity transition. Theme changes recolor retained code off the UI thread and reject stale results. At 100% zoom, messages and the composer share the main app’s centered 624 px column, shrinking with narrow panes; composer text uses 20 px lines and grows to 120 px. Renders messages using the canonical server Markdown parser, syntax classifier, and core message presentation. Supports code, tables, nested emphasis, links, edit summaries, command/goal cards, and expandable tool timelines. Hidden messages remain hidden. The conversation and input shell have internal vertical padding. Tool timeline headers and their outer layout remain transparent; only expanded details have a card background.
- The composer has a native animated border beam while focused or running. Response, code-block, and tool-detail Copy controls briefly show a checkmark after copying, with repeated clicks restarting the confirmation. Markdown paragraphs, code blocks, and user text support drag selection and Cmd+C; selection across separate blocks remains unfinished. Activity uses the animated dot matrix and elapsed time without redundant Thinking/Writing labels above the composer. Active runs show elapsed time beginning immediately on Send/Enter above the composer, with a single Stop control inside the typing shell. Live startup/working stages appear in the transcript. Tool rows retain connected milestones, connector source labels, expandable results, and a pulsing active-call dot. Codex MCP, dynamic-tool, and web-search calls are admitted at start and retain independently keyed results. Skill proposals provide Review changes, current/proposed instructions, Approve & save, Reject, persisted outcomes, stale-update protection, and access to the Skills library. Skill reads and plugin proposals have summary cards; plugin proposal application and embedded app/link previews remain unfinished. Native text sending and Stop use the authenticated live connection and saved conversation directory/provider settings. Enter sends, including follow-up messages during an active response through the backend’s existing steering/queue policy; the Stop button remains separate. Queued follow-ups and pending steering use compact rows above the input in a scrollable 112 px region and refresh on reconnect. Waiting messages can be edited, saved, cancelled, or removed through the canonical queue service; failed saves retain the edit. Shift+Enter inserts a newline. Failed requests retain the draft, and edits made during request preparation are preserved. Native multiline editing supports clipboard, grapheme deletion, selection, vertical movement, undo/redo, and UTF-16 IME ranges. Opening Settings takes focus away from the composer; closing restores it.
- Image attachments support PNG, JPEG, WebP, and GIF through the native file picker and chat-pane file drops, with removable draft photos in a horizontal strip above the typing shell. Sent messages stack bounded paper-and-tape photo cards above their text. Image viewports clip tall/wide sources and reserve space before decoding, preserving transcript layout at every zoom level. Sending uploads images through the authenticated backend; image-only messages are supported and failed sends retain attachments. Unsent image attachments currently remain in memory only.
- Repository history uses shared graph projection and virtualized rows, verified author images, branch-specific WIP rows, and stable repository identity when selecting another worktree. Current changes have staged/unstaged lists and per-file/group stage actions. Enter toggles the selected file between staged and unstaged through the shared keyboard policy, advancing within its section or retaining the moved file when it was last. Historical details put author/message left and files right; expanded mode uses a right sidebar. Diff geometry, changed-region navigation, and the minimap publish as soon as Git finishes; syntax colors prepare afterward without blocking display. Split/unified views share before/after syntax data. Prepared files are retained in an eight-entry cache with a 24 MiB payload budget per repository; immutable commit hits publish synchronously, while working-tree hits revalidate through Git before reuse. Neighboring commit files prefetch geometry at low priority; working-tree navigation avoids redundant prefetch Git reads. Same-size edits, index changes, commits, and late recolors cannot substitute stale content. Split/unified diffs preserve syntax context and reuse already-open contents. A red/green overview rail marks all changed regions, shows the viewport, and supports click/drag scrolling. Space and Shift+Space jump to the next/previous changed region, wrap at the ends, and work while either the diff or file list is focused. Opening a diff starts at its first changed region. Overview preparation is bounded by resolution and retains changes at the end of large files.
- Settings has Database, Appearance, GitHub, Providers, MCP connections, Skills, and Folders. Native controls use authenticated loopback APIs for reads and writes. Includes provider/model/reasoning defaults, global instructions, background scenes/custom images, font/code theme, GitHub repositories and clone actions, MCP connection controls, skill editing/duplication/deletion, and folder selection. Draft edits survive refreshes. The database explorer is read-only and provides table selection, records, pagination, first-column filtering, schema, and cell previews.
- Tool calls start as plain, closed headers, including running tools, visible lifecycle hooks, and restored edits. Clicking reveals one scrollable details card with one copy control, without nested Input/Output labels or cards; completion does not open it, and a standalone `completed` result is omitted. Structured file edits show one native inline diff instead of repeating the raw payload: changed lines only, original line numbers, red/green row tints, word-level change highlights combined with syntax colors, addition/deletion counts, and Copy edited code feedback. Preparation and recoloring run with transcript workers; long edits use a bounded virtual list with horizontal scrolling. Edit details stay closed until clicked. JSON, shell commands, and direct file-tool output with known file metadata use native syntax highlighting; tool-card colors follow syntax-theme changes. Plain terminal logs remain literal text, and progress notes render Markdown emphasis. Titles come from the shared behavior mapping rather than raw tool names: reads, writes, searches, URL research, commands and lifecycle steps. Visible lifecycle hooks read as Starting session, Reading request, Preparing action and Processing result. Internal stop-hook records remain in the transcript but have no visible row or expandable details. Timeline segments join dot centers, including across hidden rows and expanded details, and stop at message-group boundaries.
- Cmd+B toggles the sidebar, Cmd+, opens Settings, Escape returns, and Cmd+Q quits. Cmd+plus (or Cmd+=) and Cmd+minus zoom the entire interface from 50% to 200%; Cmd+0 resets to 100%. Zoom persists through the shared preferences service and applies in chat, repository views, Settings, and focused text fields. Layout, typography, custom input geometry, and resize calculations use the same scale. Native title bars retain a 96 px physical inset and at least 42 px height so macOS controls stay clear at every zoom; the controls remain vertically centered. In the repository, ↑/↓ selects commits/files, → opens files, and ← returns to the graph. Home/End and Alt+↑/↓ use shared graph navigation; Space/Shift+Space page the diff.

Native design tokens, icons, and syntax palettes live in `assets/` and `src/colors.rs`; no build-time extraction from the old renderer remains. Shared image/provider assets still live in `public/`. Markdown/highlighting are exported by `inferay-server`, not compiled again by source path. Keep `native/core`, `native/presentation`, `native/diff-engine`, and `native/server`: these own shared application behavior.

## Verification

```sh
cargo test --locked --manifest-path native/gpui/Cargo.toml
cargo clippy --locked --manifest-path native/gpui/Cargo.toml --all-targets -- -D warnings
cargo fmt --manifest-path native/gpui/Cargo.toml -- --check
```

Tests cover global zoom with composer and Settings focus, zoom persistence and input geometry, Enter staging in linked worktrees, coalesced streaming and turn-clock boundaries, stale theme publication, Enter/newline/IME behavior, stop request targeting and failure recovery, first-message visibility, long transcript virtualization and viewport resizing, profile restoration, draft isolation, focus restoration, dirty settings refresh, authenticated settings persistence, profile ownership, authenticated WebSocket snapshots/local-command updates, graph geometry, worktree isolation and staging, diff syntax, and rich transcript interpretation. Persistence tests use temporary profiles and staging tests use temporary repositories. UI checks also use a separately identified QA bundle for mutations. Native Enter-to-send was verified with the local `/help` command, including persisted history and an independent retained draft. Background-window captures sometimes retain an older presented frame until a resize; foreground/background redraw behavior still needs investigation.

`vendor/gpui-pre-apple` contains narrow CoreText weight, alpha-blending, and shadow-clipping fixes. `vendor/gpui-pre-macos` retains the native dark window material. See `NOTICE` and the included Apache license. Upstream Cocoa deprecation warnings remain in these framework dependencies.

Repository membership: the picker and sidebar show checkout paths and provide Remove from project controls. Removal uses the shared project command, preserves checkout files, reports automation/tool dependencies, and selects another repository or closes the panel when the last one is removed. The sidebar can add a repository when the list is empty.

Repository refresh: the visible history panel refreshes on the existing five-second repository poll, including external branch checkouts and linked-worktree changes with unchanged file counts. Hidden panels wait until reopened.

Repository parity: linked worktree WIP rows stay beside their loaded HEAD instead of appearing at the top when that commit is outside the history page. Path/Tree controls, collapsible directories, and aggregate additions/deletions are available for current changes and commits. The repository left edge and lower detail panel (side panel when expanded) have resize handles. These sizes currently remain local to the open preview.

## GPUI-only release milestone

The 2026-10-26 cutover deletes the former UI and host in one commit. The production bundle keeps `com.inferay.app`, `/Applications/inferay.app`, the existing Inferay Dock icon, and the existing user profile. `packages/inferay` remains the npm installer/launcher; the release command builds the GPUI DMG, updates both GPUI manifest and lockfile, and publishes the existing npm/GitHub artifacts.

Production GPUI checks for updates on launch and every 15 minutes. Available updates open Settings → About & updates, where Update and restart uses the shared installer backend. External-backend development sessions cannot initiate installation or restart their owning backend. Local builds verify packaging; publishing and a real downloaded-version upgrade are separate release operations.

Provider requests render native per-question inputs and action-specific approve-once/decline controls. Interrupted queued turns show an explicit Retry action. Chat snapshots retain the requested recent window across reconnects; Load older messages expands it while preserving the reading anchor.

Typing `/` in the composer opens the live native skill and command catalog, including custom skills. Prefix filtering, Up/Down, Enter/Tab selection, Escape dismissal, mouse selection and Manage skills use the existing command API and Skills settings. Selection inserts into the draft rather than sending it. Resumed agent turns refresh skill names, descriptions and revisions while keeping captured session instructions.
